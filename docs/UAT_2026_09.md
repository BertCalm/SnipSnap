# UAT pass, September 2026

A user-acceptance review of the app as it stands: ten simulated journeys
across three personas, run against the real `:shell` state machines, plus a
read of the Compose layer for the things a state machine can't show you —
what's hidden, what's unlabelled, and what a first-time user will never
find.

**Method, and its honest limit.** The Android app cannot be launched in
this environment (no SDK, no device), so nothing here is a screenshot.
What *is* real: every journey below was executed as code against the same
models `:app` binds to — `StarterKits`, `InstantKit`, `ChopReviewModel`,
`KitBuilderModel`, `ExportWizardModel`, `TapeDeckModel`, `PadSheet`,
`Preflight`, `Exporters`. Tap counts, timings, refusal wording, preflight
verdicts and format outputs are measurements, not estimates. Everything
about *layout* — what fits on a 390 dp frame, what a gesture looks like —
is read off the source and marked as such. The harness is
`shell/src/test/kotlin/com/snipsnap/shell/UatSimTest.kt`; it asserts
nothing and writes a full transcript to `uat-transcript.txt` in the JVM's
system temp directory (`java.io.tmpdir`).

```
./gradlew :shell:test --tests '*UatSimTest*'
```

---

## The headline

The engine room is in extraordinary shape. Sixteen pads of real DSP render
in 172 ms. Eight export formats all wrote clean files on the first pass.
Preflight blocks an empty kit and passes a good one. Refusals are specific
and in plain words — TUNE on a kick comes back *"only 1% of the sound lives
in its partials"*, which is better error copy than most shipping audio
software manages.

The problem is not the machine. It's that **the app never tells anyone
what it is.**

Three findings do most of the damage, and all three are cheap:

1. **HELP describes a product that no longer exists.** It says
   *"THIS IS THE M0 SKELETON… CAPTURE ARRIVES WITH M1."* Capture, chop,
   synth, groove, play and export have all shipped. The one screen a
   confused user opens tells them the app can't do the thing they just
   watched it do. The title bar still reads `M0` beside it.

2. **There is no first run.** No tour, no "here's the loop", no example.
   `Copy.BOOT_LINES` — the boot litany, already written — is never shown
   at boot; it only appears inside the stale HELP screen. A new user lands
   on an empty shelf holding one button and a joke.

3. **Roughly half the app's depth is behind one 480 ms hold that nothing
   on screen mentions.** PAD SHEET — 20 treatments, SHAPE, TUNE, MUTATE,
   LAYERS, TAKES, and the door to GRAIN FIELD — has no tap path and no menu
   entry. It is taught by a toast that fires on at most three kit-opens and
   then retires forever. The code already knows this: `PREF_PAD_SHEET_HINTS`
   in `App.kt` documents a prior audit reaching the same conclusion. The
   hint is a patch over a structural problem, not a fix.

## Journey notes

### J1 · New user, cold start → a kit on the MPC — **6 taps**

The best path in the app, and it works.

```
[1] shelf: "NOTHING TAPED YET. GO STEAL A SOUND (LEGALLY)."
[2] NEW KIT ▸ STARTERS  →  PICK A STARTER (8 entries, each with a blurb)
[3] FACTORY             →  DUBBING… 172 ms, 16 pads, auto-opens KIT
[4] EXPORT              →  preflight 3× OK, 17 files queued
[5] DESTINATION         →  system folder picker
[6] WRITE KIT           →  FACTORY.xpm
```

The starter menu is the single best-designed thing in the app: eight
options, each with a one-sentence blurb that predicts the result, and
EMPTY GRID sitting first and honestly named. `NEW KIT ▸ STARTERS` is a
good label — it predicts a menu, not a recording.

Picking EMPTY GRID instead is the one cold-start cul-de-sac: 0 pads,
`"16 EMPTY PADS. TERRIFYING."`, and the only instruction is a toast you
get by tapping a pad — LONG-PRESS TO CAPTURE. Preflight correctly refuses
to export it (`[FAIL] no pads assigned — nothing to export`), which is the
right call, arrived at three screens too late.

### J2 · Capture something in the room — **5 taps on the fast path**

ARM → SNIP works, the armed UI is well judged (level meter *and* a ticking
mm:ss, so a silent room can't be misread as a dead app), and the optimistic
SNIP toast is corrected if the commit actually fails. Good.

But **the snip goes somewhere the user isn't**. After SNIP, nothing
navigates. The snip is in SNIPS, which is a button near the bottom of the
shelf below BACKUP. The path the app clearly wants — TAPE → INSTANT KIT,
which produced a playable 4-pad kit in 95 ms — is not the path the SNIP
button points at, because it points at nothing.

### J3 · Arguing with the classifier

Classification was confident and correct on the test material (KICK 0.91,
SNARE 0.88/0.95, CLAP 0.70) and the NOT SURE dashed chip is exactly the
right piece of honesty. The placement summary line — `AUTO-PLACE: KICK→A01
SNARE→A02` — is genuinely good copy.

The cost is finding #6: a 10-state one-way cycle is the wrong control for
a 10-value choice. A grid of ten chips in a sheet would be one tap.

### J4 · Export fan-out — all 8 formats wrote clean

| format | landed |
|---|---|
| MPC 2 FOLDER | `FANOUT.xpm` |
| EXPANSION | `FANOUT/` |
| XPN ARCHIVE | `FANOUT.xpn` |
| MPC 3 NATIVE | `FANOUT.xtd` |
| MPC SESSION | `FANOUT.xpj` |
| MIDI GROOVES | `FANOUT Preview.mid` |
| SFZ | `FANOUT.sfz` |
| DECENTSAMPLER | `FANOUT.dspreset` |

Zero failures, zero exceptions. The pipeline is the strongest part of the
product and the wizard around it is the weakest-supported: eight one-way
taps and no explanation of what any of them mean.

### J5 · The depth behind the hold

Every one of the 20 segments applied successfully on a real kick sample:

```
CRUSH → sp1200 18ms    TAIL  → smeared 102ms   GHOST → ghosted 162ms
TAPE  → tape   13ms    SLAP  → slapback 12ms   STOP  → stopped  17ms
DIRT  → mpc60   7ms    WASH  → washed   34ms   START → started  19ms
SKIM  → skimmed 480ms  PUNCH → punched  41ms   FLIP  → reversed 32ms
DUB   → dubbed  247ms  BODY  → bodied  114ms   SWELL → swelled  59ms
WOBBLE→ wobbled  46ms  ETERNAL→ eternal 1773ms
TUNE  → refused: "only 1% of the sound lives in its partials"
```

That refusal is a highlight. It declined to retune a kick, and it said why
in language a musician understands. That's the standard the rest of the
app's copy should be held to — and mostly is.

### J6 · Day 5, a shelf with history

Seven kits in, the shelf is already thin: no sort, no search, no dates, no
"on card" state, no art. Every row is `NAME · N PADS · DRAFT`. This is the
screen that degrades fastest with success — a user who likes the app will
have 40 kits by month two and no way to navigate them.

### J7 · Edges — handled well

Silence chops to 0 slices and INSTANT KIT refuses with a *useful* message
(*"no hits found to chop — trim closer to the sound, or use CHOP's grid"* —
it names the alternative). Name validation is correct and its refusal
copy spells out the forbidden characters. Marking OUT before IN swaps them
rather than erroring. The export stage machine refuses illegal transitions.

Two gaps: silent overwrite (#18), and `Ünïcödé` is refused with no
transliteration offered — reasonable for MPC safety, but a user with a
non-ASCII keyboard hits a wall the copy doesn't help them past.

### J8 · Power-user ceiling

EVIL TWINS lit 16 bank-B pads in 118 ms; ghost layers built 3 velocity
zones; IN KEY moved exactly the 4 tonal pads and left the drums alone
(right call, and it says so); the 35-file deep kit exported clean.

Two ceilings: bank B is uneditable (#11), and DESAMPLE on a
velocity-layered pad refuses with *"clear the layers before rewriting its
audio"* — correct and clear, but there's no "clear the layers" button
offered next to the refusal.

### J9 · The trim deck

Physics ported from the prototype; snap-to-onset and snap-to-zero both on
by default, which is the right default. Selection snapped cleanly to
onsets. Zoom is a 3-state one-way cycler (x1 → x2 → x4) with no pinch —
mild, but it's the third one-way cycler in the app.

### J10 · The frame

Covered in findings #1, #2, #9, #10, #22, #23.

One note on PERSONALITY: at OFF, toasts are drawn at alpha 0. The
accessibility reasoning in `Chrome.kt` is careful and correct — the live
region is still composed for TalkBack. But a *sighted* user at OFF loses
every confirmation the app gives: no "kit deleted", no "shared", no
"renamed". OFF is presented as a tone setting; it currently doubles as a
feedback setting.

## What's working, and shouldn't be touched

- **The starter menu.** Eight options, honest blurbs, EMPTY GRID first and
  correctly named. Cold start is solved.
- **Refusal copy.** Nearly every refusal names the cause and often the fix.
  The TUNE and INSTANT KIT refusals are better than most commercial audio
  software.
- **Preflight.** Blocks what's broken, passes what isn't, shows its work as
  a checklist. Exactly right for a tool that writes to someone's SD card.
- **The armed-capture indicator.** Level meter plus wall-clock counter,
  anchored to a real timestamp so a remount doesn't lie about session
  length. That's a detail most apps get wrong.
- **The bins.** Pads, rooms and kits all get a 30-day bin with visible days
  remaining and a restore. Destructive actions are genuinely reversible.
- **The accessibility pass.** The September audit's fixes are real:
  `tapeClick` forces an explicit label decision at every call site, and
  the KDoc explaining *why* a label is null is better documentation than
  most codebases have for the accessible path.
- **Performance.** 172 ms for a 16-pad kit, 95 ms for a live chop. The
  thin-shell-over-proven-code bet paid off.

---

## If only three things get fixed

1. **Rewrite HELP and drop the `M0` tag** (hours). It is the cheapest
   possible fix and the app currently misrepresents itself to every user
   who looks for guidance.
2. **Give PAD SHEET a visible door** (a day). A `PAD ▸` chip in KIT's
   action row, or a persistent one-line legend under the grid the way
   ROOMS already has one. The long-press can stay as the fast path.
3. **Turn the two one-way cyclers into pickers** (a day). Ten class chips
   in a sheet; eight format rows with a line of explanation each. This is
   the difference between a tool that feels fast and one that feels like
   it's making you count.
