## What is implemented in the application

Three existing finite presets are registered in the shared factory roster: **Pearl Close,
Coral Reply and Kelp Passage**. FRESH TAPE has a fixed **NACRE** starter using the new layered
bank. User-preset promotion retains the complete Nacre recipe, including the renderer,
native note/velocity, macros and full 64-bit seed. Earlier saved renderers remain replayable.

The bank contains sixteen pads and 48 mono 44.1 kHz PCM24 samples. Each sample retains its
full six seconds, 264,600 frames. It is a finite one-shot bank with no rack FX, sample loops
or programmed choke relationship between different pads.

- A01–A08: Pearl Close at MIDI 48, 51, 53, 55, 58, 60, 63, 65.
- A09–A12: Coral Reply at MIDI 48, 51, 55, 60.
- A13–A16: Kelp Passage at MIDI 48, 51, 55, 60.

| Trigger velocity | Native source velocity | TOUCH | Fixed sampling gain |
| --- | ---: | ---: | ---: |
| 1–41 | .30 | .05 | 5.8020506 |
| 42–84 | .65 | .18 | 1.8642224 |
| 85–127 | 1 | .30 | 1 |

Velocity zero belongs to no sample zone. The hard source is the accepted ordinary preset
performance, not a separately normalized render. The gain law removes only explicit source
amplitude factors so the sampler owns playback velocity:

```text
effort(t) = .22 + .78 * t^.65
samplingGain = effort(.30) / (sourceVelocity * effort(sourceTouch))
```

This is input-based compensation, not output peak/RMS matching. The v1 bank keeps model 3,
seed 7, note and the remaining controls fixed across a pad's layers. Grouping rendering by
note reuses the four-entry source cache rather than building another cache.

The typed source field is `nacreVelocityLayers`; its policy is
`native-velocity-and-touch-effort-v1`. `NacreVelocityKits.recipeFor()` validates the exact
v1 model, source settings, windows and gains. **The new study values are not valid
drop-in replacements under that unchanged policy.**

`NacreVelocityRecipe.renderAllLayers()` renders complete layer history. Generic one-source
editing and REPLAY refuse layered targets. Standalone sidecars fingerprint every velocity
WAV using optional `rawVelocitySha256`; legacy sidecars without it remain readable. Backup
tests verified bundle/audio/window retention. At the feature baseline, generic backup did
not restore every ordinary main recipe, key or layer label: do not equate complete typed
bundle retention with unrestricted editor-history restoration. Recheck later generic changes.

## What changed in the November 7 audition

Josh reported that the differences were hard to tell. Source/file inspection found:

- All 48 delivered WAVs were unique and matched their manifest hashes; duplicate bindings
  were not the cause.
- The old layer handler paused audio, changed the correct source and reset time, but never
  called `play()`. Even MIDI 64 → 65, within the same Medium zone, reset all sixteen players.
  Different card players could also overlap.
- The v1 layers vary native velocity and a narrow TOUCH range, then remove their dominant
  explicit amplitude factors. They retain the same body modes and base damping law.
- The three presets have identical TOUCH .30, DUET .15 and CURRENT .20. Their main
  differences are return amount/path: Pearl BLOOM .15, Coral BLOOM .35, Kelp BLOOM .35 with
  VENUE 1. Public BLOOM does not change played-string damping because the core is frozen.

The revised Site uses one shared C3 player, immediate play/restart buttons, common monitor
volume, source labels and short A/B/C sequences. Quick comparisons use 1.2 seconds per
source, a six-millisecond excerpt-end fade and 250 ms gaps. Full comparisons retain six
seconds per source with 750 ms gaps. Individual full source WAVs are unchanged. The full
bank browser now solos playback and leaves same-zone slider changes uninterrupted.

**This UI revision is Site-only.** The application generator still produces the original
bank browser. Running `generateNacreVelocityKit` will not reconstruct the November 7
comparison or its seven studies. Do not overwrite the deployed Site index with that generated
index; retain the Site source or port the control changes deliberately in a later round.

### Seven unpromoted candidates

All are actual Kotlin renders at C3/MIDI 48, seed 7, model 3, native velocity 1, full six
seconds. These have measurements, not a new listening approval.

| Contact choice | TOUCH | Listening gain |
| --- | ---: | ---: |
| Gentle contact | 0 | 2.6210661 |
| Accepted reference | .30 | 1 |
| Firmer contact | .65 | .7123289 |
| Full contact | 1 | .5766346 |

Contact gain is `effort(.30) / effort(TOUCH)`. No output matching was applied. The .30
reference exactly matches the published hard Pearl C3 hash. TOUCH .65 showed the largest
measured contact contrast: normalized early spectral distance .15364 versus .05417 for the
current Soft layer, with gain-removed attack residual .40161 versus .13967. Its RMS was
.05299 versus .05327 for the reference. These numbers do not establish that Josh will hear
enough difference, and the sequence is not a monotonic brightness ladder.

| Return choice | BLOOM | VENUE | Gain |
| --- | ---: | ---: | ---: |
| Minimum returns | 0 | 0 | 1 |
| Strong coral | .85 | 0 | 1 |
| Strong kelp | .85 | 1 | 1 |

These retain TOUCH .30, DUET .15 and CURRENT .20. **Minimum returns is not dry**: the model
has built-in return floors. Stronger returns add energy, so these are not equal-loudness
matched. The measured coral/kelp spectral distance was .30864 after power normalization.

Seven selected study WAVs were finite, mono PCM24, ended at zero, peaked at no more than
.6852, had maximum absolute DC about .0000497, and retained C3 within 2.3 cents. Strong coral
triggers the generic `never_grows=false` probe because its delayed answer can exceed its
initial 100 ms; this is a bounded feed-forward arrival, not evidence of feedback instability.
Do not describe the result as “every probe passed.”
