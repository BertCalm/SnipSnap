## What is implemented

SPARK is one THUMP voice, not a separate engine. It produces finite mono
44.1 kHz hits using 4× internal synthesis. Its controls and defaults are:

| Control | Default | Main purpose |
|---|---:|---|
| TUNE | 0.50 | Root, 110–440 Hz; the default is 220 Hz |
| DECAY | 0.35 | Body t60, 0.16–1.0 s; output lasts about 1.4× t60 |
| PUNCH | 0.50 | Source rise and strike/body articulation |
| METAL | 0.25 | Inharmonic material through the body |
| COLOR | 0.50 | Independent body/edge spectral shaping |

R3 uses a finite 31-partial harmonic body alongside sine phase modulation and
a sine/finite-triangle ring product. Modulation and ring loss resolve toward
the pitched body. Pitch fall is fixed, so METAL and COLOR no longer alter that
same pitch gesture. PUNCH spans a rounded 60 ms rise to a 0.6 ms strike using a
squared control law. SPARK passes amount 0 to the legacy shared PUNCH shaper,
then uses one uniform house-level gain after decimation. See `THUMP_SPARK.md`
and `Thump.spark` for the exact mappings and conditioning sequence.

`ThumpFamilies.patches` makes 2–16 ordered, independently editable snapshots.
Default positions are 0, 1/3, 2/3, 1. For offset `position - 0.5`, METAL and
COLOR receive `+0.70 × offset`, DECAY receives `-0.30 × offset`, and TUNE/PUNCH
stay fixed. Resolved values clamp to 0..1. Each patch saves its complete map;
this is separate-hit expression, not continuous movement inside a ringing hit.

Integration boundaries remain deliberate:

- SPARK is in the SYNTH picker. Fresh SEND classifies the delivered audio;
  reopened-pad identity follows the existing app policy. Nominal PERC styling
  is not a promise that every render classifies as PERC.
- `ThumpPresets.forVoice(SPARK)` remains empty. No factory bank was approved.
- DE-SAMPLE excludes SPARK from its candidate grid.
- No HOLD, MOVE, seamless-loop, live-controller or within-hit motion feature
  was added. The audition's XPM kit is a 16-pad MPC2 proof; phone performance
  and MPC hardware loading remain unchecked.

## Portable player

The [reference ZIP](assets/2026-11-07-spark-r3-player.zip) includes the current
HTML/JS/CSS, unchanged contrast manifest and all 12 original native/matched WAVs.
It is self-contained for the three-pair task. Optional historical links in its
HTML point to the hosted Site; those pages still require the Site owner's access.
No credentials, Git metadata, hosting identity or full historical collection
are in the package.

Extract it into a new directory and run there:

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

Open `http://127.0.0.1:8080/`. Serve at the HTTP root; `file://` cannot handle
the absolute asset paths and manifest fetch. There is no build or dependency
installation. Its local browser state starts fresh; the completed owner result
is recorded in this document and the ZIP's README, not injected into a new
browser's answers.

Package receipt: 19 entries, 934,879 bytes. SHA-256:

```text

```

`CHECKSUMS.sha256` covers the payload. `SOURCE.json` records canonical source
hashes and the sole intentional change: optional history hrefs in the portable
HTML use absolute hosted URLs. JavaScript, CSS, manifest and audio are exact
copies of the Site snapshot. The manifest retains its November 4 creation-time
“no listening verdict yet” text; the November 7 decision here supersedes it.

### Reproduce or change code

Use JDK 17, as the validated CI did. A historical local JDK 21 run hit an
internal compiler failure in unchanged Caustic code; that was not a SPARK test
assertion. Read the current `AGENTS.md` and Steward before future code changes.

Focused current-code check:

```sh
./gradlew --no-daemon :synth:test \
  --tests com.snipsnap.synth.ThumpSparkTest \
  --tests com.snipsnap.synth.ThumpFamiliesTest
```

For exact historical generator provenance, inspect the working tree first,
fetch the pinned commit and use a separate worktree:

```sh
git status --short
git fetch origin f1dd98447e3ef8c8fe0c6884568bef63670a0d63
git worktree add --detach ../snipsnap-spark-r3 f1dd98447e3ef8c8fe0c6884568bef63670a0d63
cd ../snipsnap-spark-r3
./gradlew --no-daemon :synth:generateThumpSparkAudition \
  -PsparkOutput=/absolute/fresh-r3-folder \
  -PsparkBaseline=/absolute/preserved-r2-audition
./gradlew --no-daemon :synth:generateThumpSparkSweetSpots \
  -PsparkSweetSpotOutput=/absolute/fresh-fine-study \
  -PsparkSweetSpotBaseline=/absolute/preserved-r3-audition
```

Use unused worktree/output paths. The optional baseline arguments require the
actual preserved files; omitting them produces no preserved comparison proof.

Full history remains in the separate Site Git snapshot.

For production code changes, run the full JVM suite under the current repository
rules: `./gradlew --no-daemon test` without an Android SDK, or add `-x :app:test`
when an SDK includes `:app`. Current CI shards synth tests; a plain local `test`
still runs the complete suite. Run the native checks if C++ or its build changes,
and the Android compile/device paths for relevant app work.

## Why it is built this way

- A THUMP voice gives the oscillator/filter idea a small integration surface.
- Fixed R3 synthesis keeps new listening comparisons tied to the accepted sound.
- Endpoint contrasts establish a meaningful difference before fine preferences.
- Preserved WAVs and complete recipes make the result auditable and editable.
- Separate app and Site snapshots protect newer product work from old web exports.
