# Finite MURMUR RR bank import

The Instruments bench offers IMPORT RR BANK beside the separate RR shelf. Android Files supplies a content URI for one ZIP. The importer derives the bank name from its bounded embedded manifest; renaming the ZIP does not rename the bank. Choose a ZIP whose root is the existing `murmur-round-robin-bank.json` plus `take-1` through `take-4`, preserving each complete child packet and its names/bytes. A wrapper directory, one fixed-take export, an ordinary v1 instrument or a ZIP of loose samples is refused. The current shelf admits only the finite STEADY ROOT C2 bank: 84 cells across seven zones, three touches and four takes of one setting. It does not admit held sources or add distinct voices.

No source is rendered and no saved models, accepted audio, ordinary v1 import/player or shelf admission rules change. SAF content bytes are read on IO into a fresh private cache directory. The caller owns/closes its stream; the pure importer closes only its ZIP wrapper and removes only its owned stage. Every payload becomes a new regular file; ZIP Unix link attributes are never materialized as filesystem links. A link-marked payload can only be ordinary bytes that must satisfy the exact existing bank closure and hashes. Relative paths, depth, names, duplicate entries, prefix collisions, counts, declared-independent actual byte consumption and directory payloads are checked before parsing/admission. No arbitrary provider filesystem path is trusted, and an existing bank is never overwritten.

The importer consumes at most 65 MiB of compressed input, expands at most 64 MiB, and allows 128 files/160 entries. The top manifest is capped at64 KiB and other metadata at8 MiB before parsing. The tiny JSON reader retains its existing depth and duplicate-key guards. Extracted bank and admission copy may coexist: cache entry requires161 MiB usable (two64 MiB banks +32 MiB reserve +1 MiB metadata), and shelf admission separately checks its target filesystem. Input buffers are16 KiB; no complete ZIP byte array is retained by the production adapter. A provider may block a read; cancellation sets an immediate flag and remains visibly busy until that read and cleanup complete. This does not promise prompt provider IO interruption.

The unchanged `MurmurRoundRobinShelf.admitSaved` verifies the full source/recipe/descriptor/WAV/PCM/hash closure, finite profile and memory policy, copies and validates a separate stage, then commits with one no-replace move. Invalid bytes or cancellation before commit leave no visible bank; prior entries remain byte-identical. Once admission returns, a late cancel does not undo success. Postcommit cleanup failure returns the saved handle with an explicit warning; its private residual remains in the cache for recovery. Precommit cleanup failure is suppressed onto the original refusal instead of replacing it. Hash validation establishes internal consistency, not trusted authorship, native provenance or owner listening approval.

The UI remembers cancellation and busy ownership, disables duplicate requests, queues a selected URI until STARTED, and cancels on STOP/disposal. Work does not block the composition. Backgrounding cancels the flag rather than cancelling the coroutine result, so a late committed success can still refresh the actual shelf. Disposal can drop an IO coroutine's return after an atomic commit; the next shelf listing discovers any committed bank. The success message follows actual admission and refreshes the RR shelf. Errors give no false partial-import success. Users can open the imported bank through the existing separate RR Keys route.

Fourteen new pure host tests cover byte-preserving admission from a synthetic84-cell saved fixture, caller-stream ownership, prior-bank collision, modified WAV refusal, hostile paths/root layouts, duplicate/prefix collisions, raw/expanded/count budgets, directory payload/manifest caps, early and mid-operation cancellation, provider failure, linked cache/namespace refusal late commit cancellation and honest success with an explicit private-staging cleanup warning. Results must be read from the source-bound gate receipts: this document claims no executed tests. Existing passed gates are not rerun by authoring. All actual App main Kotlin/Compose sources require compilation at this candidate, followed separately by ordinary full-app packaging, real SAF/Compose lifecycle interactions, Android native/audio behavior, runtime memory and physical-device checks. No new audio export or listening decision is created by this code change. The retained real bank ZIP still requires separate source-bound packaging/publication; source paths alone are not phone delivery.
