# Finite MURMUR RR shelf and Keys route

This slice adds an explicit ROUND-ROBIN INSTRUMENTS shelf section and a separate Keys route for banks already admitted by `MurmurRoundRobinShelf`. It uses the dedicated owned player from `round-robin-owned-loading.md`. Ordinary v1 sidecars still open the existing `KeysScreen` and `InstrumentPlayer`; their namespace, saved source/model formats and audio are unchanged. The only shared KeyPad change exposes the existing gesture implementation within the UI package and permits a more accurate disabled accessibility reason, with the ordinary default unchanged.

The shelf validates and lists the separate RR namespace on IO, reports loading/refused entries, and offers refresh. **Device provisioning remains open:** this slice does not add an RR bank import/admission UI, bundle the retained bank, or make ordinary instrument import understand RR. An empty RR shelf says that no RR instruments are saved. Listing an admitted bank is not evidence that the retained 84-cell bank has reached a device.

The screen remembers one `MurmurRoundRobinScreenSession` and its owned player for the selected shelf/name/identity. All owner access, including getters, native control, polling, blocking bank load and destruction, goes through one owned FIFO worker. The UI changes short-lived state and cancellation flags and queues work; neither the owner monitor nor a slow native route-retry snapshot is entered while holding the session monitor. Loading is busy before work starts, supports immediate cancellation, and disables keys. A failed or cancelled staged reload preserves the previous loaded owner, while clearing gestures and releasing old notes. Busy remains visible until the worker has completed the cancellation; cancellation is not misreported as a completed teardown.

KEYS uses the existing note labels. MINOR CHORDS and MAJOR CHORDS use the existing chord tool's final pitches, including its inversions, wide-root chord and add9 chord. Octave shifts transpose the whole result. A pad is disabled if any final tone is outside the bank's admitted range; pitches are never clamped or partially admitted. The session validates all input tones before deduplication and submits one whole chord through the unchanged eight-voice admission controller. Its gesture ownership keeps overlapping pitches sounding until the last gesture releases them, because the owner releases by pitch. Rejected admissions acquire no release ownership. Existing positional pad velocity is passed unchanged to the authored touch-layer selector. This implements finite PLUCK gestures and chord-tool playback; the 84 cells still mean seven zones × three touches × four takes of one selected setting, not 84 voices, additional voices or a HOLD implementation.

Mode/octave changes silence first and replace the pad composition identity, cancelling prior gestures instead of leaving callbacks with stale chord pitches. Stop, backgrounding, focus/noisy silence and disposal invalidate queued attacks. The screen initializes foreground state from the current Android lifecycle before scheduling a load; an already stopped screen cannot start loading. Start registers audio focus and can begin an unloaded session. Stop cancels loading and releases notes; disposal closes once and schedules native destruction after prior work, so late completion cannot resurrect screen state. The shared audio-focus contract remains gesture-driven silence without automatic note replay. Polling continues while actual active voices or stop debt remain, including after the final finger lifts. The unchanged owner restarts a lost native route with the same admission controller and monotonic IDs; failed restart leaves keys unavailable until reload.

The new pure host test selections are `MurmurRoundRobinScreenSessionTest` and `MurmurRoundRobinKeysLayoutTest`. They cover asynchronous busy/loading, whole final-note chord admission, velocity/range rejection, gesture overlap, refused chords, release tails/debt, cancellation and queued-attack invalidation, failed replacement, disposal and blocked native observations, route failure, and exact chord-tool pitch/layout compatibility. Their execution results belong in source-bound gate receipts; this document does not claim they passed. Compose compilation/source review is separate from runtime UI checks, ordinary full-app integration, Android native/audio behavior, device memory and physical acceptance. Device checks must still cover provisioned-bank loading/cancellation/reload, touch accessibility and layout, overlapping chords, tails, background/focus/noisy transitions, route restart and teardown. Existing owner sound and device approvals retain their original scopes. No new audio was rendered and no listening decision is created by this source-only slice.
