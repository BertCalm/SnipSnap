# SILK Phase 4 — closing the listening gate, then presets

*A plan doc, September 2026. Phase 4 was scoped by the design spec
(`docs/superpowers/specs/2026-09-27-silk-string-engine-design.md`,
"Phasing and gates") as "Presets, by ear, after each voice's gate." This
plan corrects a premise that turned out to be false once actually checked:
no voice's gate has been closed yet.*

## The debt this phase actually pays off

The spec's own phasing table says every phase "ends the house way: stop and
listen" — a page rendering that phase's voices at defaults and each
character macro's extremes, judged CLOSER/SAME/WORSE against the real
instrument. Phases 1b, 2 and 3 each *disclosed*, honestly, that this gate
was not run ("this sandbox cannot play audio") — but disclosing an open gate
is not the same as it being open by design. Re-reading `Silk.kt` now: every
macro default is still explicitly commented "a placeholder awaiting the
listening gate," and a long list of unsourced shape constants (OUD's
`RISHA_GAIN`/`SLIDE_GAIN_SCALE`, every voice's body-table gains and t60s,
SANTUR's WASH range, SHAMISEN's `SLAP_BURST_HZ`/skin t60) have never been
heard by anyone.

So Phase 4 is two things, in order:

1. **Close 1b/2/3's own gates and Phase 4's listening pass at once**, with
   one audition page covering all four voices — defaults, each phase's
   named extremes, and the shared shape parameters (BODY/DAMP/PICK/STRIKE)
   every voice carries. This is new work, not a re-run: no such page has
   existed for SILK before.
2. **Author `SilkPresets.kt` and wire `SynthScreen.kt`/registration** —
   but only after the verdict comes back, informed by it. Presets proposed
   before anyone has heard the engine are exactly the case the spec calls
   out: *"presets authored blind are disposable."* This plan does not
   pre-name presets for that reason.

## What ships in this round

**`SilkAuditionGenerator.kt`** (test main, mirrors `PluckAuditionGenerator`)
renders 16-bit clips at one loudness (`AuditionLevel.level`) under
`testkit/silk-audition/<VOICE>/`, plus the listening page copied from
`synth/src/test/resources/audition/silk-audition.html`. Per voice:

- `default` — the voice as it ships today.
- `body_0` / `body_1` — BODY's own table, since every body-table gain and
  t60 in `Silk.kt` is unheard shape.
- `damp_0` / `damp_1` — the ring/thud ends.
- `pick_0` / `pick_1` — the pick-burst brightness range (mallet hardness,
  for SANTUR specifically, is this same knob).
- `strike_bridge` / `strike_centre` — position's own two ends.
- `tune_root` / `tune_top` — SCALE's own span, sung by TUNE.
- `inflect_low` / `inflect_high` — the ±50-cent bend, unverified until now.
- The voice's own named gate extremes:
  - **OUD**: `course_0`/`course_1`, `slide_0`/`slide_1` — plus a
    `slide_1_strike_bridge` clip, since the risha tick (`RISHA_GAIN`) is
    only meant to be audible with STRIKE low.
  - **GUZHENG**: `stiff_0`/`stiff_1`, `press_0`/`press_1`.
  - **SANTUR**: `course_0`/`course_1`, `wash_0`/`wash_1`.
  - **SHAMISEN**: `sawari_0`/`sawari_1`, `slap_0`/`slap_1`.

No candidate presets are rendered in this round — see above.

**`silk-audition.html`** follows `pluck-audition.html`'s own shape: one
cassette per voice, tap-to-play pads, CLOSER/SAME/WORSE chips per clip, a
free-text note per voice, and a verdict section asking the open questions
each voice's own code comments already flag (the body table's shape, the
risha's audibility, WASH's range, SAWARI/SLAP's balance). Reactions and
notes persist the same way — local storage first, the artifact's own `db`
capability if connected, chat if not.

**`synth/build.gradle.kts`** gains `generateSilkAudition`, registered the
same way as every other engine's audition task.

## What does not ship in this round

- `SilkPresets.kt`, `SynthScreen.kt` wiring, and any roadmap row claiming
  Phase 4 shipped — those wait for the verdict.
- New macros or DSP. This is a listening pass over what already exists.
- A fix for any specific finding the verdict raises — that becomes its own
  task once there's a verdict to fix toward, the same discipline every
  prior SILK phase followed for its own review findings.

## After the verdict

Once the page's reactions/notes come back (read via the artifact's `db`
capability, or relayed in chat if that connector isn't available), the
next task is `SilkPresets.kt`: a small factory library per voice, built
from whichever defaults/shape values the verdict left alone or corrected,
following the same per-voice preset-table precedent every other engine's
own `*Presets.kt` already sets. Registration into `SynthScreen.kt`'s engine
picker follows the presets, not before — the same order RESIN's own
Task 6/68 used.
