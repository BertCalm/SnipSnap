# Scanned Chain performance preservation

`baseline-307f125.json` contains the exact pre-optimization model-2 reference
outputs from commit `307f125ef2d9ef0c4d6e6c816bb008b12a235392`.
The production classes were loaded from the untouched baseline checkout;
`ScannedChainRenderBenchmark` was compiled separately as a capture harness.
The fixture retains their recorded class identities, runtime, complete recipes,
input and physical-state hashes, diagnostics, headroom, and raw/finished PCM
hashes. It also records hashes of the baseline numeric source files.

The 27 cases cover each voice at MIDI 36, 60, and 96; five short control
combinations per voice; the exact focused contour; zero velocity; and a zero
source. The shared `cases("preservation")` descriptors must continue to match
every saved recipe. Expected audio is never generated by the optimized code.

The fixture was extracted from `before-preservation.json`, SHA-256
`bf81eed9b9afe624a043caa778b60347ee773901e609150a29ae43c55a1c8f7d`.
Only each case's timing measurements and the report's timing/cancellation
metadata were removed. Host timing observations belong to the benchmark
reports, not to correctness assertions.

The test independently hashes little-endian IEEE-754 float32 raw bits and
checks every physical ledger field. It also verifies retained results after
later work, changed-control A/B/A isolation, and two simultaneous real solvers.
Existing completed-cache tests cover cancellation and cache publication races.

Keep this baseline unchanged for performance-only work. A deliberate change to
the instrument needs an explicit compatibility decision and a separately
identified reference, rather than replacing the expected hashes with new output.
